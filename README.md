# پیمان الکترونیک

فروشگاه آنلاین پیمان الکترونیک در دو بخش:

- **محصولات پیمان**: محافظ برق (لوازم خانگی، چندراهی، ساختمان و سه‌فاز) و تجهیزات اعلام حریق (کنترل پنل، دتکتور، شستی و آژیر). این محصولات را خود پیمان الکترونیک تولید می‌کند و پنج سال گارانتی دارند.
- **قطعات و ابزار**: برد توسعه، سنسور، قطعات پسیو و ابزار الکترونیک.

ساخته‌شده با Next.js 16 (App Router، Cache Components)، React 19، TypeScript و Tailwind CSS 4. رابط کاربری کاملاً فارسی و راست‌به‌چپ است.

## اجرا

نیازمندی: Node.js نسخه 22.13 یا بالاتر (برای SQLite داخلی Node).

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # بیلد production
npm run start    # اجرای بیلد
npm run lint
```

## تنظیمات (متغیرهای محیطی)

فایل `.env.example` را به `.env.local` کپی کنید و مقدارها را پر کنید:

| متغیر | کاربرد |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | نشانی دامنه در production، مثل `https://peyman-elec.ir`. در توسعه خالی بماند تا درگاه به localhost برگردد |
| `ZARINPAL_SANDBOX` | پیش‌فرض `true` (درگاه آزمایشی). برای پرداخت واقعی `false` |
| `ZARINPAL_MERCHANT_ID` | کد ۳۶ نویسه‌ای مرچنت زرین‌پال؛ در حالت آزمایشی لازم نیست |
| `DATABASE_PATH` | مسیر فایل SQLite سفارش‌ها؛ پیش‌فرض `./data/peyman.db` |
| `ADMIN_PASSWORD` | رمز ورود به `/admin` (حداقل ۸ نویسه). بدون آن، بخش مدیریت غیرفعال است |

## خرید و پرداخت

1. مشتری در `/checkout` مشخصات گیرنده را وارد می‌کند.
2. سرور قیمت و موجودی را دوباره از کاتالوگ حساب می‌کند (قیمت ارسالی از مرورگر استفاده نمی‌شود)، سفارش را در SQLite ثبت می‌کند و مشتری را به زرین‌پال می‌فرستد.
3. زرین‌پال مشتری را به `/api/payment/callback` برمی‌گرداند. سرور پرداخت را با API تأیید (verify) زرین‌پال و مبلغ ذخیره‌شده بررسی می‌کند و فقط در صورت تأیید، سفارش را «پرداخت‌شده» علامت می‌زند.
4. مشتری در `/order/<شناسه>` رسید را با کد سفارش و کد پیگیری می‌بیند. اگر پرداخت ناموفق باشد، دکمه پرداخت دوباره نمایش داده می‌شود.

مبالغ در سایت به تومان و در تراکنش زرین‌پال به ریال است (×۱۰).

### راه‌اندازی پرداخت واقعی

1. در [زرین‌پال](https://www.zarinpal.com) درگاه بسازید. برای فعال شدن درگاه معمولاً نماد اعتماد الکترونیکی (اینماد) لازم است.
2. `ZARINPAL_SANDBOX=false` و `ZARINPAL_MERCHANT_ID` را روی سرور تنظیم کنید.
3. `NEXT_PUBLIC_SITE_URL` را روی دامنه اصلی بگذارید و دوباره build بگیرید. نشانی بازگشت درگاه `https://<دامنه>/api/payment/callback` است.

## بخش مدیریت

در `/admin` با `ADMIN_PASSWORD` وارد شوید.

- **سفارش‌ها:** وضعیت پرداخت، مشخصات گیرنده، اقلام و کد پیگیری زرین‌پال.
- **محصولات** (`/admin/products`): افزودن، ویرایش، مخفی‌کردن و حذف محصول؛ تغییر سریع قیمت و موجودی از همان فهرست. تغییرات بلافاصله در فروشگاه دیده می‌شوند.
  - نشانی صفحه محصول (slug) بعد از ساخت ثابت می‌ماند تا لینک‌ها و رتبه گوگل خراب نشوند.
  - مشخصات فنی را هر ردیف در یک خط به شکل «عنوان | مقدار» بنویسید.
  - برای توقف فروش، به‌جای حذف، تیک «در فروشگاه نمایش داده شود» را بردارید.
  - مدت گارانتی هر محصول را به ماه وارد کنید: ۶۰ یعنی پنج سال و صفر یعنی بدون گارانتی. این فیلد پیش‌فرض ندارد تا برای قطعات، که گارانتی پیمان ندارند، اشتباهی گارانتی ثبت نشود. گارانتی روی کارت محصول، صفحه محصول و داده ساختاریافته گوگل نمایش داده می‌شود.

## موجودی انبار

- موجودی فقط بعد از پرداخت موفق کم می‌شود؛ ثبت سفارش و پرداخت ناموفق موجودی را تغییر نمی‌دهند.
- اگر موجودی کالایی در فاصله ورود مشتری به درگاه تا بازگشت تمام شود، پرداخت تأیید (verify) نمی‌شود، سفارش «ناموفق» ثبت می‌شود و زرین‌پال مبلغ را خودکار به مشتری برمی‌گرداند.
- صفحه‌های سبد خرید و تکمیل خرید قیمت و موجودی را مستقیم از پایگاه داده می‌خوانند. اگر قیمت در فاصله باز بودن صفحه تغییر کند، سرور سفارش را با مبلغ جدید ثبت نمی‌کند تا مشتری مبلغ تازه را ببیند و دوباره تأیید کند.

## ساختار

| مسیر | محتوا |
|---|---|
| `src/data/` | دسته‌بندی‌ها، استان‌ها و محصولات نمونه (فقط برای پر کردن اولیه پایگاه داده). دسته‌بندی‌ها از اینجا تغییر می‌کنند، نه از بخش مدیریت |
| `src/lib/site.ts` | نام فروشگاه، تلفن، شهر، آستانه ارسال رایگان و هزینه ارسال |
| `src/lib/catalog.ts` | خواندن کش‌شده کاتالوگ برای صفحه‌های فروشگاه (با `"use cache"`) |
| `src/lib/products.ts` | خواندن و نوشتن مستقیم محصولات در پایگاه داده |
| `src/lib/pricing.ts` | محاسبه جمع سفارش و هزینه ارسال؛ مشترک بین مرورگر و سرور |
| `src/lib/db.ts`، `src/lib/orders.ts` | پایگاه داده SQLite، migrationها و مدل سفارش |
| `src/lib/zarinpal.ts`، `src/lib/payment.ts` | اتصال به درگاه زرین‌پال |
| `src/lib/admin-auth.ts` | نشست ورود مدیر (کوکی امضاشده) |
| `src/app/` | صفحه‌ها و مسیرها |
| `.claude/skills/` | اسکیل‌های Claude Code برای طراحی، React/Next.js و SEO فروشگاهی |

## میزبانی

محصولات و سفارش‌ها در یک فایل SQLite روی دیسک ذخیره می‌شوند. بنابراین سرور باید Node.js 22.13 یا بالاتر و دیسک ماندگار داشته باشد، مثل سرور مجازی یا سرویس‌هایی مثل لیارا با دیسک. پلتفرم‌های serverless بدون دیسک ماندگار مناسب نیستند.

- وقتی پایگاه داده ساخته یا به‌روز می‌شود، هر دسته‌ای که هنوز محصولی ندارد، محصولات نمونه خودش را از `src/data/sample-products.ts` می‌گیرد. بعد از آن این فایل دیگر خوانده نمی‌شود.
- `npm run build` را روی همان سرور و با همان `DATABASE_PATH` اجرا کنید تا صفحه‌های از پیش ساخته‌شده با داده واقعی بسازند.
- **پشتیبان‌گیری:** پایگاه داده در حالت WAL است. یا سرور را متوقف کنید و هر سه فایل `peyman.db`، `peyman.db-wal` و `peyman.db-shm` را کپی کنید، یا در حال اجرا از دستور `sqlite3 data/peyman.db ".backup backup.db"` استفاده کنید.

## پیش از راه‌اندازی عمومی

این موارد هنوز نمونه یا جای‌نگهدار هستند:

- **محافظ‌ها و تجهیزات اعلام حریق نمونه‌اند:** مدل، مشخصات فنی، قیمت و موجودی همه را از بخش مدیریت با محصولات واقعی خود جایگزین کنید. اگر محصولی تأییدیه یا استاندارد دارد، مثل تأییدیه آتش‌نشانی یا استاندارد ملی، آن را در مشخصات بنویسید. در نمونه‌ها عمداً ادعایی از این نوع نیامده است.
- قیمت و موجودی قطعات و ابزار نمونه
- تلفن، شهر، آستانه ارسال رایگان و هزینه ارسال در `src/lib/site.ts`
- ادعاهای نمایش‌داده‌شده در سایت: پنج سال گارانتی (`warrantyYears` در `src/lib/site.ts`)، ارسال رایگان، و «ضمانت اصالت» در صفحه قطعات
- تصویر محصولات: فعلاً به‌جای عکس، آیکون دسته نمایش داده می‌شود

## گام‌های بعدی
